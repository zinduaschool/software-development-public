# 01. HTML & CSS (Introduction to Programming)

**Official Curriculum for Introduction to Programming Course in the Software Development Program**


## **Course Objective**

To provide learners with a strong foundation in frontend web development and modern developer workflows. By the end of the course, learners will be able to structure web pages using HTML, style responsive interfaces with CSS and Tailwind CSS, manage projects using the Command Line Interface (CLI), track and publish work using Git and GitHub, document projects using Markdown, and design interfaces in Figma. The course intentionally focuses on **core Tailwind CSS skills**, preparing learners for future frameworks such as React without introducing framework-specific component libraries at this stage.


## **Skills to be Learned**

* Code Editor & IDE (Visual Studio Code)
* CLI (Command Line Interface)
* HTML5 (Semantic HTML)
* CSS3 (Responsive Design & Layouts)
* Git & GitHub (Version Control)
* Markdown (Technical Documentation)
* Tailwind CSS (Utility-First Styling)
* UI Design Fundamentals
* Figma (Design-to-Code Workflow)

## **Assessment Rubrics**

Assessments are designed to evaluate both **technical competence** and **professional workflow practices**. Rubrics below guide instructors in grading consistently across cohorts.


### **Week 1 Assessment: HTML, CLI, GitHub & Markdown Foundations**

**Deliverable:** Basic HTML website published on GitHub with a README.md

| Criteria                             | Excellent (4)                                                      | Good (3)                                            | Satisfactory (2)                           | Needs Improvement (1)                  |
| ------------------------------------ | ------------------------------------------------------------------ | --------------------------------------------------- | ------------------------------------------ | -------------------------------------- |
| **HTML Structure & Semantics** | Correct document structure, proper semantic tags used consistently | Mostly correct structure with minor semantic issues | Basic structure present, limited semantics | Invalid or poorly structured HTML      |
| **CLI Usage**                  | Confidently uses CLI to create, navigate, and manage files         | Uses CLI with minor assistance                      | Limited CLI usage, relies on GUI           | Does not demonstrate CLI understanding |
| **Git Usage**                  | Clean commit history with meaningful messages                      | Commits present but messages are generic            | Few or unclear commits                     | No meaningful commits                  |
| **GitHub Repository**          | Repository properly set up and accessible                          | Repository exists with minor issues                 | Repository incomplete or poorly organized  | Repository missing or inaccessible     |
| **Markdown README**            | Clear, well-structured README with headings and formatting         | README present with basic formatting                | Minimal README content                     | README missing or unreadable           |


### **Week 2 Assessment: CSS & Responsive Layouts**

**Deliverable:** Responsive landing page using HTML and CSS

| Criteria                            | Excellent (4)                                         | Good (3)                                    | Satisfactory (2)                 | Needs Improvement (1)         |
| ----------------------------------- | ----------------------------------------------------- | ------------------------------------------- | -------------------------------- | ----------------------------- |
| **CSS Syntax & Organization** | Clean, well-organized CSS with consistent naming      | Mostly organized with minor inconsistencies | Disorganized but functional CSS  | Broken or unreadable CSS      |
| **Box Model & Layout**        | Correct use of margin, padding, and layout properties | Minor spacing/layout issues                 | Basic layout with visible issues | Layout broken or inconsistent |
| **Responsiveness**            | Fully responsive across screen sizes                  | Mostly responsive with small issues         | Limited responsiveness           | Not responsive                |
| **Visual Consistency**        | Consistent fonts, spacing, and colors                 | Minor inconsistencies                       | Inconsistent styling             | No clear styling consistency  |

### **Week 3 Assessment: Tailwind CSS, Git Workflow & Documentation**

**Deliverable:** Tailwind-based website with professional README

| Criteria                               | Excellent (4)                                            | Good (3)                          | Satisfactory (2)               | Needs Improvement (1)               |
| -------------------------------------- | -------------------------------------------------------- | --------------------------------- | ------------------------------ | ----------------------------------- |
| **Tailwind Utility Usage**       | Efficient, intentional use of utilities                  | Good usage with some redundancy   | Overuse or misuse of utilities | Incorrect or minimal Tailwind usage |
| **Responsive Design (Tailwind)** | Responsive classes used correctly throughout             | Minor responsive issues           | Limited responsive classes     | No responsive design                |
| **Git Workflow**                 | Logical commit history reflecting development progress   | Adequate commit history           | Infrequent or unclear commits  | No clear workflow                   |
| **Markdown Documentation**       | Well-structured, detailed README with images or sections | Clear README with minor omissions | Basic README                   | Poor or missing README              |

### **Final Project Assessment: Design-to-Code Implementation**

**Deliverable:** Figma design + Tailwind website + GitHub repository

| Criteria                          | Excellent (4)                                          | Good (3)                      | Satisfactory (2)                      | Needs Improvement (1)     |
| --------------------------------- | ------------------------------------------------------ | ----------------------------- | ------------------------------------- | ------------------------- |
| **Figma Design Quality**    | Clear layout, consistent spacing and typography        | Good design with minor issues | Basic design with limited consistency | Poor or incomplete design |
| **Design-to-Code Accuracy** | Code closely matches Figma design                      | Minor mismatches              | Significant visual differences        | Design not followed       |
| **Tailwind Implementation** | Reusable patterns and clean utility usage              | Mostly clean usage            | Redundant or inconsistent utilities   | Poor Tailwind usage       |
| **Project Completeness**    | All required sections implemented                      | Minor missing elements        | Several missing sections              | Incomplete project        |
| **Documentation Quality**   | Comprehensive README with screenshots and explanations | Good documentation            | Minimal documentation                 | No documentation          |
| **Professionalism**         | Clean repo structure and clear presentation            | Mostly professional           | Some disorganization                  | Unprofessional or unclear |

### **Grading Scale Recommendation**

* **90–100%:** Distinction / Excellent
* **75–89%:** Pass with Merit
* **60–74%:** Pass
* **Below 60%:** Incomplete / Needs Improvement

### **Instructor Notes**

* Prioritize understanding and consistency over visual perfection
* Encourage frequent commits and iterative improvement
* Use rubrics formatively, not only summatively
* Provide actionable feedback aligned with each criterion
